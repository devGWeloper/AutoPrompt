# 데이터셋 폴더

## 한 일

데이터셋 하나 안에서 케이스를 폴더로 나눌 수 있게 했고, 폴더만 골라서 실행할 수 있게 했습니다.

## 왜

한 데이터셋에 요약형, 멀티턴형 같은 다른 성격의 케이스가 섞여 있었습니다.

- 유형 하나만 보고 싶어도 전체를 다 돌려야 했습니다.
- 점수가 하나로 뭉쳐 나와서, 어느 유형이 나쁜 건지 알 수 없었습니다.

## 만든 것

**데이터셋 화면**

- 왼쪽 데이터셋 목록에서 데이터셋을 고르면 그 아래에 폴더가 펼쳐집니다.
- `+ 폴더`로 만들고, 마우스를 올리면 이름 변경 · 삭제가 나옵니다.
- 폴더를 누르면 그 폴더의 케이스만 보입니다.
- 케이스를 추가하면 지금 보고 있는 폴더로 들어갑니다.

```
▍고객상담셋              24
   전체                  24
   요약                   5
   멀티턴                 4
   폴더 없음              3
   + 폴더
 다른셋                  12
```

**실행 화면**

- 데이터셋 옆에서 폴더를 고릅니다. `전체 (24) / 요약 (5) / 폴더 없음 (3)`
- 폴더가 하나뿐이면 안 나옵니다.

**기록 화면**

- 어느 폴더를 돌렸는지 같이 보입니다. `고객상담셋 · 요약`
- 이게 없으면 5건 돌린 실행과 24건 돌린 실행이 똑같아 보여서, 나중에 점수를 잘못 비교하게 됩니다.

## 정해둔 규칙

- 폴더 이름을 바꾸면 그 안의 케이스도 같이 따라갑니다.
- 폴더를 지워도 케이스는 안 지워집니다. `폴더 없음`으로 나옵니다.
- 빈 폴더는 실행이 안 됩니다.
- 폴더는 데이터셋마다 따로입니다. 다른 데이터셋과 안 섞입니다.
- CSV로 들어온 값 중 폴더에 없는 것도 목록에 보이고, 같은 이름으로 폴더를 만들면 그 케이스들이 들어갑니다.

## 같이 고친 것

- 실행 화면의 `As-is` 버튼 이름을 `Default`로 바꿨습니다. 무슨 뜻인지 알기 어려웠습니다.
  기본값이라 맨 앞으로 옮겼고, 버튼에 마우스를 올리면 설명이 나옵니다.
- `대상` 고르는 자리를 `API` 앞으로 옮겼습니다.

## 참고

- 폴더를 안 만들면 지금까지와 똑같이 동작합니다.
- 기존 데이터는 그대로입니다.
- DB 반영은 `sql/migrate_case_type.sql`, `sql/migrate_run_case_type.sql` 두 개입니다.
